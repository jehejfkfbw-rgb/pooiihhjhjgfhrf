## 1) التشغيل محلياً (5 دقائق)

```bash
npm install

# .env:
# DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:5432/app_db"
npx drizzle-kit push          # مزامنة الجداول
node scripts/seed-employees.mjs   # تهيئة 18 موظفاً ذكياً
npm run build && npm start    # أو npm run dev
```

### قاعدة البيانات: المحلية (افتراضي) أو Supabase الخاصة بك

**الافتراضي:** PostgreSQL محلي عبر `DATABASE_URL`.

**على Supabase (قاعدة بياناتك السحابية):**
1. من Dashboard → Settings → API: انسخ **Project URL** و**Publishable Key**
2. من Settings → Database: تأكد من **Postgres Password**
3. في `.env` اضبط:
   ```
   SUPABASE_URL=https://[project-ref].supabase.co
   SUPABASE_DB_PASSWORD=[كلمة المرور]
   SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```
4. أنشئ الجداول على قاعدتك (مرة واحدة):
   ```bash
   DATABASE_URL="postgresql://postgres.[project-ref]:[كلمة-المرور]@[project-ref].supabase.co:5432/postgres" npx drizzle-kit push
   node scripts/seed-employees.mjs   # مع DATABASE_URL نفس السطر
   node scripts/seed-knowledge.mjs
   ```
5. شغّل — طبقة `src/db/index.ts` تبنّي الاتصال تلقائياً من SUPABASE_URL + كلمة المرور.

> ⚠️ كلمة مرور Postgres والمفاتيح في `.env` فقط (خادم) — المفتاح القابل للنشر هو الوحيد الآمن للعرض.

## 3) دورة تنفيذ المشروع (مطبقة فعلياً)

1. عميل يملأ النموذج → مشروع برمز سري + تحليل في الخلفية
2. محلل الأعمال (د. لمياء): متطلبات قابلة للاختبار + معلومات ناقصة تُسأل للعميل
3. المهندس التقني (م. طارق): بنية + قواعد بيانات
4. مدير المشاريع (م. يوسف): مهام مرتبة بتبعيات حقيقية
5. تقدير أولي للمدة (نطاق + ثقة) — يظهر للعميل والإدارة
6. **المطور يعتمد النطاق والتكلفة** من اللوحة قبل التنفيذ
7. بدء التنفيذ: بيئة عمل معزولة `workspaces/NB-XXXX/` + قاعدة بيانات
8. الموظفون ينفذون (نموذج AI أو المولّد المحلي) — ملفات حقيقية تُكتب في قرص وقاعدة
9. **فحوصات فعلية بعد كل مهمة**: `node --check`، تشغيل خادم Node مؤقت وطلبات HTTP حقيقية (health/echo/حالة خطأ 400)، فحص أسرار مضمّنة، اكتمال الملفات
10. الفشل → إعادة محاولة (حدّ 2) → فاشلة → «يتطلب تدخل المطور»
11. تحديث موعد التسليم بعد كل مهمة من الزمن الفعلي (16 تحديثاً في آخر اختبار)
12. بوابة التسليم: لا تسليم إلا إذا **كل** المهام منجزة بفحوصات ناجحة ولا ملفات فارغة
13. العميل: ZIP حقيقي + معاينة حية + رسائل + تقييم
14. إيقاف/استئناف/إلغاء فوري، واستئناف بعد إعادة تشغيل الخادم بدون فقدان التقدم

### حدود صريحة (النظام لا يدّعي فوقها)
- بيئة البناء Android/iOS غير متاحة → مشاريع التطبيقات تُسلَّم بخادم+API+مواصفات موثقة
- لا نشر إنتاجي ولا عمليات مالية ولا أوامر طرفية خارج قائمة الفحوصات الآمنة
- حدود: 30 ملفاً / 400KB / محاولتان لكل مهمة — كلها مسجلة في السجل الزمني

## 4) قاعدة المعرفة والملكية الفكرية

منظومة بيانات خاصة بالشركة (13 جدولاً مرتبطاً):
- **قاعدة معرفة (103 مدخل أولي، قابلة للنمو)**: 13 موضوعاً — أساسيات، لغات، أطر، قواعد بيانات، ويب، موبايل، أنظمة، اختبار، أمان، ممارسات، **إصلاحات أخطاء موثقة**، أدوات، قوالب. كل مدخل: **مصدر مسجّل** (official-docs/company-generated/platform-tests) + ترخيص + تاريخ + استخدام
- **مستودع الخبرات**: قرارات هندسية، دروس من الإخفاقات، إصلاحات أخطاء بعدد رصد، مكونات معاد استخدامها، سجل تقدير/فعلي
- **بحث ذكي FTS** بـ PostgreSQL (GIN index) + ترشيح (المحقق أولاً ثم الترتيب ثم الاستخدام)
- **حلقة مغلقة فعلية**: كل مهمة تسحب المعرفة ذات الصلة (RAG) وتزيد استخدام المدخلات → كل مشروع مسلَّم يحصد خبراته (قرار + دروس + مكونات + تقدير/فعلي) → تقديرات المشاريع الجديدة **تُعاير من السجل التاريخي** (تُطبق تلقائياً عند 3+ مشاريع من نفس النوع)
- **تبويب «قاعدة المعرفة»** في اللوحة: بحث، تصفح، تحقق يدوي، إضافة مدخل، خبرات المشاريع، دقة التقديرات
- **العزل**: المعرفة خبرة شركة داخلية — لا بيانات عملاء، لا خلط بين المشاريع، وجميع المسارات 401 بدون جلسة
